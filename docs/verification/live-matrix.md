# Live verification matrix — LIVE-01 … LIVE-24

> Purpose: turn the architectural promises of Phase 1 into executable rows. Every row states the assertion,
> the mechanism that must exist to check it, whether it is automatable, who owns it, and its honest current
> status. **In this iteration the connector does not exist, so almost every row is a specification.** The
> rule from `docs/adr/0020` governs the table: an unexecuted row is `SKIPPED`/`NO`, never `PASSED`.

Preconditions and variable semantics: `docs/verification/live-env-contract.md`.

Status legend — `NO — Phase 2`: not executed, blocked on the connector · `PARTIAL`: a Phase-1 artefact checks
part of it statically · `YES`: executed and recorded in this iteration.

## Rows that are NOT in the matrix, and why

| Candidate | Why excluded |
|---|---|
| "Popup opens in under N ms" | a performance target, not a correctness assertion; belongs to the parity matrix in `37-ui-architecture.md` §9 |
| "Xray version is the latest upstream" | ADR-0019 pins a *specific* release on purpose; newer-is-better is not an assertion |
| "The extension passes `web-ext lint`" | deliberately deferred: with today's manifests it would fail on rules that are Phase-2 work (`docs/audit/10-manifest-packaging-distribution.md`) |
| "UI shows a green tick for a healthy server" | a UI state, not a fact about the tunnel; `LIVE-04` is what the tick is allowed to mean |

## Promotion rules

1. A row may move to `YES` only with: date, host, connector + Core versions, the exact command, and the raw
   output archived under `docs/verification/logs/`.
2. `LIVE-04` must be `YES` before any of `LIVE-05…LIVE-09` may be reported as `YES` — egress proof is a
   precondition of a transport claim, not a companion.
3. A row that regresses is re-set to `NO` with the failing log attached; it is never re-labelled `SKIPPED`.
4. `Verified: NO` rows must appear in `docs/architecture/39-verification-matrix.md` so no design document can
   quote them as fact.

## Honest summary of this iteration

Twenty-four rows are specified; **one** is partially executed (`LIVE-14`, the compile half, against the legacy
engine rather than a browser). Nothing in this iteration may be reported as a working VLESS or REALITY
connection: the connector does not exist, Go is not installed on the development host, and the one Phase-1
artefact that claims protocol knowledge — `packages/schema` — is checked only for self-consistency, which is
exactly what it can be checked for before any protocol code exists.
